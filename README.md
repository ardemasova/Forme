# Forme — AI Interior Design Studio

Концептуальный продукт для портфолио: «AI‑дизайнер интерьера», который помогает человеку понять свой вкус, собрать moodboard и подготовить бриф для профессионального дизайнера. Интерфейс сайта — на испанском.

> **Важно.** «AI‑агент» здесь — продуктовая концепция. Текущая реализация работает на **локальной детерминированной демо‑логике** (дерево сценариев + веса предпочтений + правила). Языковые модели, внешние AI API, Telegram API, сервер, база данных и авторизация **не используются**. Telegram показан как интерактивный mockup внутри сайта. CRM работает на демонстрационных и локально сохранённых данных.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
# или продакшн-сборка
npm run build && npm start
```

Ключи API и переменные окружения не нужны.

## Публикация на GitHub Pages

Проект собирается как статический сайт (`output: "export"` → папка `out/`). В репозитории есть workflow `.github/workflows/deploy.yml`.

1. Создайте репозиторий и запушьте код в ветку `main`.
2. **Settings → Pages → Source: GitHub Actions.** Каждый push в `main` собирает и публикует сайт.
3. Свой домен: **Settings → Pages → Custom domain**, затем DNS у регистратора:
   - поддомен (`forme.example.com`): `CNAME` → `<user>.github.io`;
   - корневой домен: `A` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
   После проверки включите **Enforce HTTPS**.

Путь `/<repo>` для адреса `<user>.github.io/<repo>` подставляется автоматически; со своим доменом сайт работает от корня.

### Как работает демо‑логика агента

1. Каждое действие пользователя превращается в **сигналы** `{тег, вес, источник}`: выбор атмосферы, отмеченные аспекты, свободный текст, выбор в проверке гипотезы, деталь, «нравится / не подходит / сохранить», исправления профиля.
2. Сумма весов по тегам даёт **профиль**: предпочтения, антипредпочтения и неопределённые гипотезы. Уверенность: «Ya se nota» (несколько согласованных сигналов) или «Aún explorando».
3. Профиль проецируется на 7 **направлений** (минимализм cálido, japandi, wabi‑sabi, claridad arquitectónica, ecléctico, mid‑century, modernismo sobrio) — отсюда палитра и описание.
4. **Гипотеза** выбирается правилами по первым ответам (тепло / ясность / экспрессия / противоречие «спокойствие + выразительные детали») и проверяется парой изображений. Ответ «ни то ни другое» уводит сценарий в ветку «что раздражает».
5. **Рекомендации** — ранжирование пула по скалярному произведению профиля и тегов изображения; отклонённое исчезает и тянет вниз свои теги, следующие карточки пересчитываются сразу.
6. «¿Por qué?» строит объяснение из реальных сигналов пользователя (какие теги совпали и откуда они взялись).
7. Всё — чистые функции от сохранённых ответов: изменение раннего ответа пересчитывает профиль, moodboard и бриф, а зависимые ответы (гипотеза/деталь) сбрасываются, только если вопрос изменился.

Никакой случайности и выводов о личности за пределами интерьерных предпочтений.

### Telegram Demo

Mockup телефона в стиле Telegram, окрашенный в палитру Forme. Действия (выбрать, сохранить в moodboard, «не подходит», «почему?», быстрые ответы, свободный текст) — это намерения, которые обрабатывает `lib/telegram/bot.ts`: ответ записывается в общий проект (канал `telegram`), бот добавляет реплику. Студия, бриф и CRM видят те же изменения. Если проекта нет, бот начинает с выбора атмосферы и создаёт проект.

### Хранение

`localStorage`, версия схемы `1`:

- `forme:v1:projects` — проекты по `conversationId` (ответы, текущий шаг, история Telegram, снапшоты профиля / moodboard / брифа / диалога, `updatedAt`);
- `forme:v1:active` — активный проект;
- `forme:v1:crm` — статусы и заметки дизайнера.

Ошибки чтения/записи перехватываются и показываются уведомлением; «Empezar de nuevo» удаляет проект только после подтверждения. Персональные данные не собираются.

## Ограничения прототипа

- Нет настоящего ИИ: понимание свободного текста — словарь ключевых слов с простыми отрицаниями.
- Каталог ограничен ~40 референсами, поэтому рекомендации со временем заканчиваются.
- Проекты живут только в одном браузере; CRM не синхронизируется между пользователями.
- Экспорт в PDF — через диалог печати браузера; дополнительно доступен `.md`.
- Вложения в Telegram‑демо не поддерживаются.
